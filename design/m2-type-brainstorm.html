레거시 타입 테스트 케이스. M2의 성공 기준은 이 의도가 살아남는 것이다.

basics · data · match · cap_row · bounds · resume · assoc_types … 전부가 1차 범위는 아니다. 어디까지 자를지가 결정 A.

규칙 언어는 이미 잠겨 있다

infer_C MIR -> TypeC with Γ infer_V Ident { name: $name } -> $return := $return = Γ.$name infer_V TypeAssignment { expr: $e, ty: $t } -> $inferred := $inferred = (check_V $e <- $t)

D-08/16/17/23/24/25: λProlog식 관계 규칙, with Γ+{a: b} 확장, 골당 정확히 한 규칙 성공, 엄격 감소 재귀, 태틱은 subst와 hash 둘뿐. 이 표면은 건드리지 않는다.

Gap 1 · MIR.syn.langue

MIR 타입 문법에는
row도 forall도 없다

지금 (D-36)

TypeV = U(TypeC) | named[args] TypeC = F(TypeV) | (TypeV, …) -> TypeC

확정 문법 (D-41 · 2026-07-11 반영)

TypeC = F(TypeV) / {Cap[args], ..r}? | (TypeV, …) -> TypeC | forall a, …. TypeC kind 문법 없음 — arity 검사만 (D-40)

해소됨: row는 F에만 직렬화(D-41), forall은 arity-0 바인더(D-40). Lumo 표면의 / {…} 표기를 MIR이 그대로 따른다.

Gap 2 · elab

elab이 타입 표기를 버린다

M1 elab: (x : Number) → ret x

fn id(x: Number) -> Number ↓ elab 후 타입 정보 소멸 fix id = thunk { λx. ret x }

제안: def 단위 어노테이션 보존

fix id = (thunk { λx. ret x } : U((Number) -> F(Number)))

spine-local 양방향 추론(D-08)은 def 서명에서 출발한다. Lumo 타입 표기를 MIR TypeV로 번역하는 규칙이 elab에 추가되어야 한다 — (v : TypeV) 자리는 이미 문법에 있다.

결정 A

M2 범위를 어디서 자르나

A1 · 코어만

basics + hof + recursion + annotation. 데이터 타입과 cap을 M3로. 판단 엔진 검증에는 충분하지만, 91케이스 중 절반이 다음 마일스톤으로 밀린다.

채택 · D-39

A2 · 코어 + data/match + cap-with-rows

위에 더해 data 선언, match 분기 타입, capability row 검사까지. resume · bounds · assoc_types · match 완전성 · cap 고정점 추론은 명시적으로 유예 — 이 다섯은 관계 규칙만으로 안 되고 extern 태틱이나 딕셔너리 기계가 필요하다.

A3 · 레거시 전부

15버킷 91케이스 전부. extern 태틱 설계가 M2 안으로 들어와 판단 표면 검증이라는 원래 목적이 흐려진다.

fixture 배선(Gap 5)은 범위와 무관하게 필요: :infer(Lumo)가 parse | elab | judge 전체 파이프라인을 타야 한다.

결정 B

Fω를 얼마나 깊이 파나

B1 · 단형 + row만

forall 없이 시작. 문법 변경이 최소지만 hof 버킷의 제네릭 케이스가 전멸하고, D-08의 "Fω" 약속과 어긋난다.

채택 · D-40

B2 · arity 카인딩 + forall 지금, 나머지는 나중

forall과 타입 적용을 넣되 kind는 인자 개수 검사(arity)로만. kind 문법과 타입 레벨 람다는 레거시 91케이스가 한 번도 요구하지 않았다 — 필요해질 때 문법만 열면 된다.

B3 · 완전한 Fω 지금

kind 문법, 타입 레벨 람다, 고차 유니피케이션 근사까지. 검증할 fixture가 없는 기계를 먼저 짓는 셈이다.
